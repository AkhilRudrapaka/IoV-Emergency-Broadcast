# System design: trust-aware, cluster-prioritised broadcast suppression for accident alerts

This describes **what the current code does** (verified against it on 2026-11-03), why each rule was chosen, and
where it stops. Every parameter lives in `config.py`; audit evidence is in [AUDIT.md](AUDIT.md). Measured results
are in `results/urban/summaries/RESULTS.md`, generated by `python run.py experiment` (provenance in
`summaries/experiment_config.json`).

## 1. End-to-end path

| # | Stage | Code | Input → output |
|---|---|---|---|
| 1 | Mobility | `scenario.py` | seed → SUMO run (1 s steps) up to the incident second; positions, speeds, lanes |
| 2 | Watchdog trust | `scenario.py`, `clustering.beta_trust` | per-second observations → Beta reputation per vehicle |
| 3 | Incident + alert | `scenario.build`, `create_alert` | random honest vehicle at t ~ U{60..120} s → one DENM-like alert |
| 4 | Neighbour tables | `channel.geometry` | snapshot → unit-disk adjacency (vehicles + RSUs), standing in for beacons |
| 5 | Clustering + CH election | `clustering.elect_roles` | positions, speeds, trust → role CH/BRIDGE/MEMBER, tier 0/1 |
| 6 | Corroboration + authentication | `corroboration.py`, `Protocol.on_receive` | proposal → committee votes → BLS aggregate certificate |
| 7 | Dissemination decision | `protocols.Proposed` (baselines alongside) | first accepted copy → timer → FORWARD or SUPPRESS |
| 8 | Transmission + reception | `channel.Channel`, `simulate` | slot-level 802.11p CSMA/CA; collisions, hidden terminals, half-duplex |
| 9 | Duplicates | `Protocol.on_alert` | per-event state: a duplicate is counted, feeds the coverage test, never re-processed |
| 10 | CH-to-CH route (a stage of the proposed method, not a separate algorithm) | `infrastructure.shortest_route`, `protocols.CHRoute` | Dijkstra over reputable CHs to an RSU; per-head local quorum |
| 11 | RSU delivery | `rsu.py`, `infrastructure.persist` | decode → verify → plausibility checks → register once per event ID; the CH-to-CH route stage's delivery → local dispatch outbox |
| 12 | Measurement + display | `metrics.py`, `report.py`, `figures.py`, `demo.py`, `demo_pairs.py`, `web_results.py` | channel log → metrics; recorded run → SUMO-GUI replay; comparison pairs (one scenario, a baseline-only and a proposed-only run, each writing its own record, compared only when the two records have the same fingerprint) → dashboard |

The dissemination runs on the **incident snapshot**. The slowest run takes 64 ms; at ≤ 19.3 m/s a vehicle moves
≤ 1.25 m, under 1 % of the 300 m range (audit SCE-7).

## 2. Rules, formulas, parameters

**Radio (channel.py).** IEEE 802.11p, 10 MHz, 6 Mbit/s. Slot 13 µs. AIFS(AC_VO) = SIFS 32 µs + 2 × 13 µs = 58 µs,
rounded up to 5 slots. CW = 3, broadcast (no ACK, no retry). Airtime = 40 µs + ⌈(22 + 8·(payload + 38 B)) / 48⌉ · 8 µs:
alert 300 B = 39 slots, certified alert with 4 signers = 50 slots, proposal = 48, vote = 21. Unit disk R = 300 m for decoding,
carrier sense and interference. A reception is lost if any overlapping transmission is in range of the receiver
(hidden terminals included) or the receiver itself transmits. Not modelled: fading, capture, EIFS, background beacon load.

**Trust.** trust = (s + 1)/(s + f + 2), from one watchdog observation per second for every vehicle with a neighbour.
An honest relay is missed with p = 0.10. A misbehaving vehicle (10 %) relays a watched frame with probability
`MALICIOUS_COOPERATION`. The default 0 is a persistent black hole whose trust is ≤ 0.5 by construction, so detection
is near-perfect. With 0.5/0.9 it is an on-off attacker (sensitivity sweep `onoff`). Threshold for trusted roles: 0.7.

**Clustering and CH election.** DBSCAN on positions (ε = 40 m, MinPts = 3). DBSCAN noise vehicles are BRIDGE.
Within each cluster, greedy set cover over the 300 m radio disk elects CHs among trusted members: maximise newly covered members,
break ties by the lowest mean relative speed to neighbours. **tier 0** = trusted CH or BRIDGE, otherwise **tier 1**.
(Measured: about one CH per cluster, because the 300 m disk covers a 40 m cluster; audit SCE-13.)

**Corroboration and authentication, kept separate.**
* The *committee* is the 5 nearest in-range neighbours of the source with trust ≥ 0.7. A member that observes the event signs
  `digest = H(event_id | type | source | seq | x | y | incident_time | created | hop_limit)` with BLS12-381. One vote
  frame of 132 B per member, rank-ordered 0.5 ms apart after verify (4.3 ms) + sign (1.4 ms).
* With ≥ 3 votes the source aggregates its own and the voters' signatures into one 96-byte signature and broadcasts the
  certified alert.
* A receiver accepts iff: the first signer is the alert's source; the signer IDs are distinct; FastAggregateVerify succeeds;
  and at least 3 endorsers have trust ≥ 0.7 (an unknown signer counts as 0). Verification costs 4.3 ms before the
  copy counts as received.

**What each check establishes.** A valid aggregate proves *who signed this exact digest* (authenticity, integrity,
non-tampering of time, position and hop limit). It says **nothing** about whether a crash happened. "Corroborated" means: at
least 3 distinct, currently reputable vehicles in radio range of the claimed position each signed that they observed the
event. That is the only accident-truth evidence the system has. It rests on two modelling assumptions: an honest committee
member observes ground truth (no sensor model), and reputation reflects behaviour (true by construction at the default, see
Trust). An RSU "REGISTERED" status therefore means *corroborated and plausible*, not *verified true*.

**Forwarding (Proposed).** On the first accepted copy, received from a sender at distance d, a vehicle schedules
`T = t_accept + (tier·Ns + S(d))·τ + U[0, RAD)`, with `S(d) = min(Ns−1, max(0, Ns − ⌈Ns·min(d,R)/R⌉))` (farthest first),
Ns = 5, τ = 5 ms, RAD = 5 ms < τ (it never reorders slots). When T fires it forwards iff some beacon neighbour (vehicle **or RSU**) is
not within range of any sender it has heard: `N(v) \ ⋃_{h∈H(v)} (N(h) ∪ {h}) ≠ ∅`. Otherwise it suppresses. Counting RSUs
as neighbours is what carries the alert to infrastructure without a routing protocol. Other rules: hop limit 10;
misbehaving vehicles receive but never relay; RSUs never relay.

**Baselines** (same corroboration, same channel): blind flooding (relay once verified); flooding + RAD; slotted
1-persistence (Wisitpongphan et al. 2007: slot S(d), suppress on any duplicate); slotted 1-p + RAD. The +RAD variants
isolate what tiers and the coverage test add beyond jitter.

**CH-to-CH route (`ch_route`).** Dijkstra by distance from the source to the nearest RSU over CHs with trust ≥ 0.7 (no
ground truth). Each route head collects a local quorum (itself + 2 cluster votes) before forwarding. Vehicles off the route stay
silent. There is no fallback: no route or a lost local quorum means no delivery on that path (reported).

**RSU.** It decodes, verifies (4.3 ms) and runs the sanity checks (fields, type, bounding box, time order, 600 s validity, hop count,
certificate). It registers the event ID once; later copies at any RSU are counted as duplicates. The dispatch is queued in a
local SQLite outbox only.

## 3. Repeated, conflicting and faulty inputs

| Situation | Behaviour (implemented unless marked) |
|---|---|
| Same alert heard again (same event ID) | Never re-processed. Counted as a duplicate; its sender is added to the coverage set; a pending timer is never restarted. |
| Same event at several RSUs | Registered once; further copies counted as `duplicate_copies`. |
| Two reports of one crash from different sources (or one vehicle reporting twice) | Each report is validated and corroborated on its own, with every rule unchanged. `rsu.register_reports` then keeps **one incident per crash**: a valid report with the same message type, an incident position within 10 m and an incident time within 2 s of **every** report already in an incident (bounds inclusive) is kept in that incident (status MERGED, its event ID and source vehicle retained) instead of being registered again. An event ID already registered is always the same report (its copies are duplicates, never a new reporting vehicle). The incident counts distinct reporting vehicles. Rejected reports are never merged, endorsements are never pooled across reports, and matches never chain (the bounds are pairwise, so one incident never spans more than 10 m or 2 s). The simulation itself still creates exactly one report per incident. |
| Conflicting report ("no accident") | No negative message type exists. Non-endorsement is silence; fewer than 3 reputable endorsers means the certificate is rejected. |
| Forged alert, colluders below the trust threshold | Certificate formed but rejected by every receiver and RSU (measured in the forgery test). |
| Forged alert, colluders with honest-looking reputation | **Accepted**: voting + BLS alone cannot stop ≥ 3 colluders (measured in the `onoff` sweep). |
| Misbehaving relay / CH (black hole) | It never transmits, so nobody counts it as coverage. Neighbours' timers still fire and forward. Cost: tier-1 latency (≤ Ns·τ). |
| Committee unavailable (< 3 reputable honest neighbours) | **Fail-closed**: the alert is never released (no timeout). Measured by `accepted`. See §5. |
| Disconnected vehicles / RSU out of reach | Not counted in reachability (`e` = source's component); RSU metrics NaN. |
| Hop limit reached | The vehicle accepts but does not relay (EXPIRED). |
| Expired or replayed alert | The RSU judges age on **its own clock** (simulation time + delay), not on the alert's claim. Older than 600 s means rejected. Refreshing `created_s` breaks the signed digest. An already registered event ID is a duplicate. |
| Duplicate vote (report) | The source counts each endorser once (`s not in self.votes`). The certificate also rejects repeated signer IDs. |

Security defaults since Block G: committee membership enforcement is on (`ENFORCE_COMMITTEE=1`: every receiver counts only endorsers in the 5-seat committee it rebuilds for the claimed position, quorum 3 of 5, so colluders outside that committee are rejected even with honest-looking reputation), the burst detector is off (`TRUST_BURST_K=0`; k = 4 is an opt-in experimental setting), and the forged-alert rows above describe the earlier rule, which `EXP_ENFORCE_COMMITTEE=0` reproduces.

## 4. Evaluation protocol

* **Matrix.** Densities 50, 100, 200, 250, 300, 500 vehicles × 30 seeds, `seed = 10000 + 100·d + r`, one incident per run. Every
  scheme runs on the *same* snapshot (paired); each scheme has its own deterministic RNG stream.
* **Schemes.** 5 baselines/proposed above; ablations `no_rad`, `no_slots`, `no_coverage`, `no_clustering`,
  `no_cluster_forwarding`, `no_reputation`, `no_security`; `ch_route`.
* **Forged-alert test.** Same snapshot. The forger is a random misbehaving vehicle with a neighbour; colluders are up to 5 nearest
  misbehaving in-range vehicles. Three protection levels: full, no reputation gate, no voting.
* **Sensitivity** (200 vehicles × 30 seeds): range {150, 300, 450} m; misbehaving share {0, 0.1, 0.2, 0.3}; on-off
  cooperation {0, 0.5, 0.9}.
* **Metrics** (definitions in the `metrics.py` docstring; collection points: channel log for frames and losses, protocol state for
  reception times and decisions, RSU registry for delivery). Key ones: frames on air; reachability r/e; t90; receptions
  lost; CBR over 100 ms; suppression = SUPPRESS/(SUPPRESS+FORWARD) among honest relays; RSU arrival (first decode)
  vs registration (+ verification); accepted share for forgeries.
* **Statistics.** Mean ± 95 % Student-t CI over defined runs (`*_n` reports how many; RESULTS.md and the final report print n wherever fewer runs than seeds had a value). Single values are shown as "(n=1)", never
  ±0. **Paired differences** (proposed − baseline, per scenario, over runs where both are defined) back any comparative claim.

## 5. Limitations and next steps

* Unit-disk radio without fading or capture; no beacon background load; small straight 5×5 grid (3–5 hops), so the hop limit
  binds only at 150 m.
* Default trust is near-oracle (persistent black holes). The `onoff` sweep is the honest stress test.
* Keys are derived from vehicle IDs (no PKI, no proof of possession). Honest observers see ground truth.
* Fail-closed corroboration (above). **Specified, not implemented:** after `QUORUM_TIMEOUT` ≈ 50 ms without a quorum
  (normal quorum ≈ 12 ms), the source broadcasts an *unconfirmed* alert with hop limit 1. Neighbours show it as unconfirmed
  and do not relay it, so there is no amplification without corroboration. An in-range RSU logs it as UNCONFIRMED, not
  dispatched.
* Reports of one crash are merged only by a conservative position/time rule (same type, ≤ 10 m and ≤ 2 s from every
  report of the incident): two distinct crashes closer than that would be treated as one, and two reports of one crash
  farther apart stay two incidents. A report within reach of two incidents joins the first registered one. The simulation
  produces one report per incident, so the rule is exercised by unit tests only. Dispatch is a local outbox only.
* The demo replays a recorded run on the identical SUMO state (verified by position and cluster asserts). It is not
  computed inside the GUI process.

## 6. Algorithm reference

Format per algorithm: **rule** · **inputs (source)** → **outputs (consumer)** · **parameters** · **edge cases / failure modes** ·
**tests** (`validation/<file>::<test>`). Parameter provenance is tabulated in §7.

**A1 Watchdog trust** (`scenario.build`, `clustering.beta_trust`).
Rule: per second, for each vehicle with ≥ 1 neighbour within R: failed = (misbehaving ∧ ¬cooperates) ∨ missed;
s += ¬failed, f += failed; trust = (s+1)/(s+f+2).
Inputs: SUMO FCD positions (`scenario.read_fcd`), misbehaving set (seeded sample), seeded RNG.
→ Output: `sc["trust"]`, consumed by A2/A3, A4, A9 and the record. Params: WATCHDOG_MISS_PROB, MALICIOUS_RATIO,
MALICIOUS_COOPERATION. Edge cases: a late-inserted vehicle has few observations (trust ≈ 0.5); a persistent black hole is
≤ 0.5 by construction (near-oracle); an on-off attacker at 0.9 passes the 0.7 gate. Abstraction: there is no relayed traffic before the
incident; an observation stands for routine relaying. Tests: test_protocols::test_trust_gates_cluster_heads,
test_pipeline::test_default_watchdog_stream_is_unchanged_and_on_off_attackers_gain_trust.

**A2 Clustering** (`clustering.elect_roles`, DBSCAN part).
Rule: DBSCAN(ε, MinPts) on 2-D positions; label −1 = isolated. Inputs: snapshot positions. → Output: `labels` (A3,
figures, demo colours). Params: DBSCAN_EPS_M, DBSCAN_MIN_PTS. Edge cases: n = 0 gives none; the `no_clustering` ablation makes
everyone isolated. Measured: ~1 CH per cluster; 65 % isolated at d = 50; 230-vehicle chains at d = 500 (audit SCE-13).
Tests: test_protocols::test_trust_gates_cluster_heads, test_pipeline::test_exactly_one_incident_and_valid_metrics.

**A3 Cluster-head election and tiers** (`clustering.elect_roles`).
Rule: per cluster, while members are uncovered, pick the trusted member maximising (members newly within R,
−mean |Δspeed| to in-cluster neighbours); stop when the best covers none. CH = picked, BRIDGE = isolated, otherwise MEMBER.
tier = 0 if role ∈ {CH, BRIDGE} and trust ≥ 0.7, otherwise 1. Inputs: labels (A2), adjacency (`channel.geometry`), speeds (FCD),
trust (A1). → Outputs: role (record, A9 planner), tier (A6). Params: TRUST_CH_THRESHOLD, COMM_RANGE_M.
Edge cases: a cluster without a trusted member has no CH (its members stay tier 1). A failed or black-hole CH only delays
others, because A6 never counts a silent node as coverage. Tests: test_protocols::test_trust_gates_cluster_heads,
::test_failed_cluster_head_does_not_suppress_its_neighbours.

**A4 Report collection and corroboration** (`corroboration.plan`, `Protocol.on_receive`, `corroboration.accept`).
Rule: committee = the COMMITTEE_SIZE nearest in-range neighbours of the source with trust ≥ 0.7. Each honest member that
observes the event sends one VOTE (a signature over the digest) after verify + sign + rank × VOTE_SLOT. The source counts
**distinct** voters and releases at ≥ QUORUM. Receivers accept iff ≥ QUORUM endorsers have trust ≥ 0.7.
Inputs: alert, adjacency, trust, misbehaving set (models who *behaves* honestly, never who is *chosen*).
→ Outputs: votes, certificate, `cert_ok` (A6 acceptance, A10 check 7). Params: COMMITTEE_SIZE, QUORUM, VOTE_BYTES,
BLS_SIGN_MS, BLS_VERIFY_MS, VOTE_SLOT_MS. Edge cases: fewer than QUORUM honest reputable neighbours means fail-closed, never released
(§5); a duplicate vote counts once; colluders below the gate are rejected; colluders above it (on-off) are accepted.
Tests: test_corroboration::test_genuine_alert_is_voted_certified_and_spreads,
::test_misbehaving_members_abstain_and_too_few_votes_means_no_alert, ::test_quorum_counts_only_reputable_distinct_endorsers,
::test_forged_alert_is_rejected_only_with_the_reputation_gate, test_protocols::test_report_collection_counts_each_endorser_once.

**A5 Authentication: BLS aggregate certificate** (`corroboration.digest/sign/certificate/verify_aggregate`).
Rule: digest = event_id|type|source|seq|x|y|incident_time|created|hop_limit. Aggregate = BLS12-381 aggregation of the
source's and the voters' signatures. Verify = distinct signers ∧ first signer = source ∧ FastAggregateVerify. The
cryptography is real (py_ecc); processing time is charged as BLS_SIGN_MS / BLS_VERIFY_MS. Inputs: alert fields, signer IDs (keys
derived from IDs: simulation only). → Output: (accepted, reason) to A6/A10. **It establishes who signed this exact content. It
does not establish that the accident happened**; that is A4's corroboration. Edge cases: an unknown signer is untrusted, not a
crash; a tampered field makes the certificate invalid. Tests: test_corroboration::test_bls_certificate_verifies_and_detects_tampering,
::test_unknown_signer_is_untrusted_not_a_crash, ::test_creation_time_and_hop_limit_are_signed,
test_infrastructure::test_batch_authentication_deduplicates_and_rejects_tampering.

**A6 Forwarding decision and vehicle duplicate suppression** (`protocols.Proposed`, `Protocol.on_alert`).
Rule: on the first certified copy, decoded at slot t from sender s: verify (4.3 ms), accept, schedule
T = t_acc + (tier·Ns + S(d_vs))·τ + U[0,RAD). For every later copy, add its sender to H(v), count a duplicate, never
re-process. At T: FORWARD iff N(v) \ ⋃_{h∈H(v)} (N(h) ∪ {h}) ≠ ∅ (vehicles and RSUs), otherwise SUPPRESS.
Misbehaving: DROP. hop ≥ HOP_LIMIT: EXPIRED. RSUs never relay. Inputs: adjacency (beacon tables), distances, tier (A3), cert_ok
(A5). → Outputs: decision + reason + decode/accept/decide times per vehicle (raw `vehicles[]`), frames (channel log).
Params: N_SLOTS, TAU_MS, RAD_MS, HOP_LIMIT, COMM_RANGE_M. Edge cases: a black-hole neighbour never counts as coverage;
RAD < τ keeps slot order; coverage needs the senders' neighbour sets (an idealised 2-hop beacon assumption).
Tests: test_protocols::test_distance_slot_farthest_first, ::test_proposed_forwards_only_for_uncovered_neighbours,
::test_misbehaving_vehicle_never_relays, ::test_relays_transmit_only_after_accepting_the_verified_copy,
test_rsu::test_uncovered_rsu_makes_a_vehicle_forward, ::test_hop_limit_stops_relaying, ::test_rsu_receives_through_a_relay_and_never_transmits.

**A7 Baselines** (`protocols.Flooding`, `protocols.Slotted1P`, `rad=True`). Flooding: relay once verified (+U[0,RAD) for
flooding_rad). Slotted 1-p: timer S(d)·τ (+RAD); cancel and SUPPRESS on any duplicate. Tests:
test_protocols::test_slotted_1p_suppresses_on_duplicate, ::test_relays_transmit_only_after_accepting_the_verified_copy,
test_channel::test_flooding_reaches_a_chain_once_per_vehicle.

**A8 Channel** (`channel.Channel`, `simulate`). CSMA/CA per 13 µs slot: AIFS restarts while the medium is busy, backoff is frozen.
Receptions are lost at receivers in range of any overlapping sender, or at receivers that are themselves transmitting.
Order within a slot: receptions → timers → contention. Tests: test_channel (timing, carrier-sense deferral, hidden terminals,
same-slot collisions).

**A9 CH-to-CH route** (`infrastructure.shortest_route`, `protocols.CHRoute`). Dijkstra (in metres) from the source to the
nearest RSU over CHs with trust ≥ 0.7, ≤ HOP_LIMIT hops. Each head on the route sends a CPROPOSAL; same-cluster reputable
neighbours answer with CVOTEs (misbehaving ones stay silent); the head forwards at itself + votes ≥ QUORUM. Edge cases: no route
(NO_CH_ROUTE) or a lost local quorum means no delivery on this path (no fallback); a misbehaving head drops the alert. Tests:
test_infrastructure::test_shortest_route_excludes_untrusted_and_non_heads,
::test_cluster_head_requires_received_quorum_before_forwarding, ::test_cluster_head_stops_when_members_cannot_vote.

**A10 RSU verification and registration** (`rsu.validate`, `rsu.register`, `rsu.register_reports`). Copies are processed in
time order. Registration time = arrival + verification. Checks: fields, type, bounding box, not received before creation,
age ≤ 600 s on the **RSU's clock**, hop ≤ hop_limit, certificate (A5 + quorum). The first passing copy is REGISTERED, later
copies DUPLICATE, failures REJECTED with reasons; every copy's status is recorded. `register` handles one report;
`register_reports` registers several reports through it, takes the valid ones in registration order and keeps one incident
per crash: a registered event ID again is DUPLICATE; a report matching every report of an incident (`same_crash`: same type
within `MERGE_RADIUS_M` = 10 m and `MERGE_WINDOW_S` = 2 s, inclusive) has its first copy MERGED. Edge cases: a stale or
replayed alert is rejected; a rejected report is never merged. Tests:
test_rsu::test_implausible_alerts_are_rejected, ::test_same_event_at_two_rsus_is_registered_once,
::test_every_rsu_copy_has_a_recorded_outcome_and_distinct_reports_are_not_merged,
::test_reports_of_one_crash_from_several_vehicles_make_one_incident, ::test_a_vehicle_reporting_the_same_crash_again_contributes_once,
::test_close_but_separate_crashes_stay_separate, ::test_a_rejected_report_stays_rejected_after_a_merge_attempt,
::test_a_single_report_is_registered_exactly_as_before, test_protocols::test_rsu_arrival_and_registration_are_reported_separately.

**A11 Metrics** (`metrics.run_metrics`, `metrics.summarize`, `experiment.paired`). Formulas are in the `metrics.py` docstring;
collection points are given in §4. Tests: test_protocols::test_suppression_ratio_ignores_hop_limited_vehicles,
::test_single_sample_has_no_confidence_interval,
::test_disconnected_cluster_is_outside_the_reach_denominator_and_rsu_metrics_are_undefined,
::test_every_decision_is_recorded_with_its_lifecycle_times, test_pipeline::test_exactly_one_incident_and_valid_metrics,
::test_full_pipeline_writes_every_output.
